# Pillxai Dispenser 系统架构

基线更新：2026 年 10 月 26 日。用户确认当前 UI 开发阶段完成，进入完整新版本实施；沿用已确认的极简界面。技术为 **Flutter + Python/FastAPI**，生产首发仍为 **Android 平板**，后续支持手机、平板、Windows 和 iOS。首次开发部署在同一电脑的 WSL/Conda 中，允许模拟机；2026 年 10 月 26 日实机联调先用 Windows 电脑连接 HC-06 蓝牙串口。M0 已运行 WSL API/PostgreSQL、生成式契约与 Windows 联调基础模块；M1 资料切片已接入真实登录、长者/处方、版本及服务端账号权限，见 [M1 报告](validation/2026-10-26-m1.md)。现已接通通用设置保存和服务端计划快照预览；任务归属、覆盖衔接、执行、后台与真实动作尚未接通或验收。本文件定义生产系统的责任边界，具体交付顺序见 [09 执行计划](09-agent-development.md)；运行入口和实际验证见[客户端说明](../apps/client/README.md)。

## 1. 产品与平台

Android 平板先交付并直接连接 HC-06，通常一终端固定一机器。资料、处方、计划、任务归属和记录使用一致的业务含义；各平台设备能力分别验证。手机、Windows 和 iOS 在后续阶段按实际需求实现，网页端不在当前首发范围。

用户已认可聚焦版的低信息密度与“处方管理”“摆药”“设置”三个入口的侧边栏，直接切换且不设返回页。主体采用白色或浅灰背景，允许灰色主背景配白色卡片，灰色用于区分层级。黑色仅为默认强调色，可由用户个性化调整；药品图片保留原本色彩。参考范围与比例要求见 06。当前采用用户已确认的单一极简风格，三个模块直接切换，不再提供视觉方案选择。真实模式中查询状态由工作区 controller 持有，演示执行仍为内存状态；两者都不能证明 Android 后台执行已实现。生产系统要求模块导航只改变界面，不改变本机执行状态；完整交互与未保存内容保护见 06。共享业务、契约与设备验证可以独立推进。

Flutter 官方支持范围及平台集成机制见 [部署平台](https://docs.flutter.dev/reference/supported-platforms)、[架构](https://docs.flutter.dev/resources/architectural-overview)、[平台通道](https://docs.flutter.dev/platform-integration/platform-channels)。实施时核查并锁定实际工具链和依赖版本。

## 2. 三个责任边界

| 边界 | 负责的工作 | 拥有的状态 |
| --- | --- | --- |
| Flutter 客户端界面 | 资料输入、待摆清单、计划核对、执行入口、记录和设置 | 页面、表单、查询缓存 |
| Python/FastAPI 中央业务服务 | 账号权限、长者与处方、计划计算、任务领取和启动许可、中央记录 | 业务事实、版本和任务归属 |
| 本机设备执行核心及平台适配 | 设备连接、顺序执行、暂停和现场处理、本地保存与结果补传 | 本机真实执行状态及待同步事实 |

这些是责任边界，不预设每个平台都运行独立后台进程。Android 首发必须具备脱离界面生命周期的执行能力；切页、切其他应用、锁屏和界面重建不能重置或停止任务。主动退出按 R12 停止并取消，异常进程终止按恢复核对处理。

## 3. 客户端组织

界面与业务模型分别组织。共享组件、表单与展示模型，按电脑、平板和手机的输入方式设计页面布局；不以一套固定尺寸页面覆盖所有设备。

客户端不直接依赖中央数据库。计划由中央业务入口根据处方、设置和覆盖计算；界面展示返回的计划，不另算一套可执行矩阵。执行按钮提交语义操作，例如开始本药、暂停、恢复、换盘和取盒；不在页面里拼接设备报文。

账号凭据、安全存储、摄像头、PDF 保存、设备连接及发布更新分别通过平台能力边界提供。各平台插件必须检查目标平台支持和维护情况，不能因包名包含跨平台就认定可用。

## 4. 中央业务

中央业务按账号身份与权限、长者、用药、计划、摆药任务、处方参数、记录导出和发布信息划分责任。中央服务与客户端独立运行，通过明确契约通信。

计划是本次决定的快照，处方是用药需要，结果是实际发生的事实；修改当前资料不能覆盖已开始任务和历史。多机在中央领取任务，任务绑定一台机器，不以全局当前长者控制所有终端。

后端使用 Python + FastAPI，以模块化单体服务起步。中央存储采用 PostgreSQL 为实施基线，配合 SQLAlchemy、Alembic 管理访问和迁移；具体版本、驱动及生成工具在 M0 锁定并实跑验证。账号权限、处方版本、任务归属和同步幂等均由服务端及数据库事务保障。客户端不连接数据库，不导入 ORM，也不通过共享文件读取中央资料。

服务器保存长者资料、处方及其他业务数据。正式部署目标包括云服务和养老院本地服务器，供机构按隐私与数据存放要求选择；院内部署时，业务数据保存在院内服务及数据库中。“中央业务”表示业务与数据的责任边界，不限定为公网云服务。两种部署沿用同一套 API 与权限规则，客户端经 HTTPS 访问选定服务，部署、备份与恢复分别验收；开发同机验证不能作为任一生产部署已交付的证据。开发测试先按下节使用同机 WSL。

### 4.1 同机开发部署

WSL 的 Ubuntu-24.04/Conda 承载 API、数据库与后端测试；Windows 运行 Flutter 或独立设备联调入口，通过 HTTP 访问 API，直接持有 HC-06 对应出站 COM。WSL 中央服务不打开 Windows 串口，也不代理逐药实时指令。之后换到 Android 时，设备连接与执行迁入平板的平台宿主，中央 API 保持同一契约。

Conda、包缓存及开发数据使用项目范围路径；可只读检查现有环境，不向已有其他项目环境混装依赖。数据库只对本机服务开放。Windows 到 WSL 的 localhost 转发必须实测；平板阶段另验 USB 调试转发或局域网连接，不把电脑的 localhost 当作平板可直接访问的地址。参考 [WSL 网络说明](https://learn.microsoft.com/windows/wsl/networking)和 [Conda 项目路径环境](https://docs.conda.io/projects/conda/en/stable/user-guide/tasks/manage-environments.html)。

数据库目录必须验证权限、事务落盘、重启与恢复；当前仓库在 Windows 挂载文件系统上，不能仅凭目录可写就认定 PostgreSQL 数据目录可用。若需要仓库之外的 WSL 原生目录或系统配置变更，实施时说明具体范围并遵守根 AGENTS.md 的授权边界。开发同机通过不代表云端或院内生产部署、备份或并发负载已通过。

### 4.2 模块和公开入口

| 模块 | 责任与公开入口 | 拥有的数据 |
| --- | --- | --- |
| identity | 登录、角色与权限校验 | 账号、会话 |
| residents | 长者资料维护与搜索 | 稳定长者身份、资料版本 |
| prescriptions | 用药维护、停用恢复、独立参数版本 | 药品与处方条目、历史、参数档案 |
| planning | 根据处方、配置、覆盖生成计划 | 不可变计划快照及来源版本 |
| tasks | 领取、启动许可、取消与占用释放 | 任务阶段、设备及人员归属 |
| records | 执行事实接收、去重、覆盖和查询 | 批次、事件、结果、同步确认 |
| labels / attachments / releases | 新标签与绑定、文件、发布信息 | 绑定历史、附件引用、发布元数据 |

各业务模块内部按需要分路由、业务服务和存储访问；公开请求响应与 ORM 分开。跨模块调用明确的业务入口，由用例协调事务，不直接改写另一模块的表；不引入微服务、消息总线或每个字段多层转发。FastAPI 路由组织参考[官方模块组织说明](https://fastapi.tiangolo.com/tutorial/bigger-applications/)。

新系统不迁移或兼容旧长者资料、处方、RFID 绑定、药品图片、历史结果、参数经验和旧数据。重新建资料、生成新标签与建立绑定，不读取旧代码建立映射。

## 5. 本机执行与设备

每台设备的命令和反馈按独立会话处理。执行核心负责当前药物和药盘、命令意图、反馈关联、计数、人工处理及允许操作；设备适配负责平台连接和报文编码。本轮优先用纯 Dart 执行核心，在 Windows 联调和模拟器中复用，核心不依赖 Widget 或平台 API。SQLite 保存本机任务及事件；存储、时钟、设备和上传入口显式注入。

执行核心、STM32 编解码、平台传输和运行宿主分别成模块。Windows 串口适配和 Android RFCOMM/USB 适配只提供字节流与连接事件；语义设备接口由协议适配器或模拟器实现。界面只订阅执行快照并提交语义操作，每台终端仅有一个执行状态所有者；UI 不再用计数定时器推进生产任务。

Android 在 M0/M3 验证由前台服务承载的独立执行运行时与 Dart 核心的连接方式。普通 Dart 后台 isolate 不自动等于 Android 后台服务，平台主动推送也存在通道限制，见 [Flutter isolate 限制](https://docs.flutter.dev/perf/isolates)。先证明服务持有连接、收包、落盘及 UI 重连均可用；若绑定方案不能满足目标平板实测，再调整核心宿主并同步唯一契约，不并存两套权威状态机。

本地持久化保存完整任务快照、执行状态、原始事件与待同步队列。执行事实与待上传项必须原子保存；收到中央确认后才标记已上传。重复上传不能重复累计结果或触发物理动作。存储实现和写入策略在基础阶段验证。

断网只继续已经开始的任务，新建资料和新任务按 02 的联网边界处理。应用或执行核心异常重启后，未知现场状态进入核对，不能自动重发矩阵。每次换盘重新识别通过后才能继续；药物处理结束后 UI 返回首页，下位机报告药盒在轨状态；离轨且设备就绪后自动释放任务，未知或失败反馈保留状态，不要求人工确认取盒。设备中断后继续、受控退出、显式结束不记录及删除重试沿用 02、03 的业务定义。

Android 以声明相应类型与权限的 `connectedDevice` 前台服务承载蓝牙执行会话，持续通知展示正在执行状态；前台服务不自动保证 CPU 持续运行，应在有效执行范围评估有界 partial wake lock 并可靠释放。实际方案以目标平板的切后台、锁屏和长任务测试决定，不能只靠页面存活或轮询定时器满足要求。

平台依据：[Android connectedDevice 前台服务](https://developer.android.com/develop/background-work/services/fgs/service-types#connected-device)、[后台任务与设备唤醒](https://developer.android.com/develop/background-work/background-tasks/awake)。

应用内退出可先持久化意图、请求停转并要求现场确认；系统 Task Manager 停止、强制停止和进程被杀不能保证获得回调或发送停止命令。划掉最近任务、正常后台和系统终止分别定义与验证，不将 `stopWithTask` 配置当作可靠硬件停止机制。普通主动关闭是否彻底删除全部记录仍待确认，明确前仅取消完成与覆盖并保留恢复证据；设备失联后是否停机必须实测。

Android 13 及以上 Task Manager 的停止操作不向应用发送回调，见[处理用户停止前台服务](https://developer.android.com/develop/background-work/services/fgs/handle-user-stopping)。因此终端被终止时的机器停机保障不能仅由 Flutter 或 Android 生命周期逻辑承担。

## 6. 三端验证

| 平台 | 必须验证的内容 |
| --- | --- |
| Android 首发平板 | 经典蓝牙直连 HC-06、权限与固定绑定、前台服务与锁屏持续执行、受控退出、强杀后恢复、新签名包手动安装与升级 |
| Windows 后续 | 串口及 HC-06 连接、页面与执行分离、退出和重新启动、安装与升级 |
| iOS | 实际可用的硬件通信方案、系统生命周期约束、本地保存、签名和发布 |

现有设备为 STM32 和 HC-06 经典蓝牙串口，具体事实见 04。不能把 Windows 的 COM 端口实现直接当成手机适配，也不能预先承诺 HC-06 可由 iOS 直接连接。后续确定 BLE、网络或网关等通信方案前，先取得设备事实并进行实机验证；本轮不更改硬件或系统配置。

## 7. 契约与验证

公开 API、执行命令和事件采用统一权威定义，避免客户端、后端、设备程序分别手写漂移的公开模型。HTTP 契约以 FastAPI 公开请求/响应模型为唯一源，导出 OpenAPI 并生成 Dart SDK，生成链在 M0 实际验证；不额外维护另一套契约源。覆盖枚举、可空值、时间、精确剂量、颗粒整数和版本冲突；本机命令与事件在执行核心公开入口统一定义，平台绑定不复制业务状态模型。生成命令、目录和阶段验收见 09。

代码质量以可读与精简为硬要求：业务命名、单一责任、显式依赖、必要注释和小而完整的模块；不为设想中的未来堆积接口层、通用引擎或重复转发，也不以压缩语句减少行数。对关键计划计算、权限、归属、设备状态和恢复做有意义的验证，普通展示不堆积镜像测试。

业务验证以 05 固定案例为输入。完整流程按资料与处方、预览、领取、识别、执行、取盒、查询和补传验证。性能、留存、安装、恢复和多机并发要求见 07。模拟结果与真实摆药结果明确区分。

当前已建立 Flutter GUI 预览，工程目录、运行命令、工具链与实际验证结果统一见[客户端说明](../apps/client/README.md)。FastAPI 与数据库基础入口已实现，HC-06 实机、后台生命周期和生产任务保存尚未验收；框架可支持的平台、文档中的验收目标和过去版本的通过记录，都不能作为 Flutter 生产版本已交付的证据。
