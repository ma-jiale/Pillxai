# Windows 上机测试

在仓库根目录执行：

```powershell
.\scripts\run-windows.ps1
```

Windows 版直接连接学校 Pillxai 服务 `https://ixd.sjtu.edu.cn/pillxai`。使用该服务器的账号登录。首次切换或修改代码后用 `-Build` 重新构建，构建前关闭空闲客户端。可执行文件位于 `apps/client/build/windows/x64/runner/Release/pillxai_client.exe`，发布时须保留同目录 DLL 与 data。

## 先走模拟机

1. 在处方管理建立明确标记“模拟”的长者与处方。可设置两种不同餐食关系的药，在预览中开启分盘，验证换盘流程。不要使用真实长者做演练。
2. 在“摆药”右上角设备按钮打开“我的设备”，选择模拟机，保存连接并连接。模拟 UID 可自行设为不重复的十六进制值；可点“开仓读取标签”，查看读取到的 UID。
3. 预览该长者的计划并进入“上机准备”。核对 UID 后绑定到这位长者，核对自动选择的初速度和舵机值，再“领取并开仓”。参数按每份处方独立保存，模拟执行的学习计算只作为模拟记录。
4. 识别匹配后“开始摆药”。可暂停/继续、切到处方或设置再返回。换盘重新识别后点“已换好，继续”。正常同盘换药无需再次开始。
5. 全部药完成后进入首页取盒提示，点模拟机专用“模拟取出药盒”，等待稳定离轨、收仓及就绪反馈。任务释放后可在右上角执行记录查看数量。

## 切换 HC-06 实机

1. 等待模拟任务结束并同步。Windows 配对现场设备（名称通常 `dispenser01`），在系统中核对它的**出站 COM**及蓝牙地址/稳定身份。候选 COM 枚举不会自动判定哪台是摆药机，历史 COM7 不能直接当作今天端口。
2. 在“我的设备 → 添加新设备”选择标有“蓝牙”的候选。使用 USB 时改为插好数据线后选择标有“USB连接”的候选。首次由维护人员在“连接设置”核对设备标识及端口（蓝牙对应出站 COM，USB 对应插线后出现的 COM），保存后工作人员按设备名称连接。程序按 115200、8N1、无流控打开，连接本身不发送命令。
3. 在“位置与反馈配置”核对早/午/晚/睡前对应协议行、日期列方向，再勾选位置已确认。`2,1,0,3` 只是当前报告中的协议映射起点，必须核对实体位置。准备少量可辨识测试计划进行现场位置测试。
4. 在现场已允许开仓时，点“开仓读取标签”，观察原始反馈；核对后将新标签绑定到测试长者。不迁移旧标签与资料。
5. 上机准备按 [04：新参数与学习策略](04-device-contract.md#新参数与学习策略)选择初速度与舵机值：无有效历史时使用 `0.2 / 0.7`，默认开启学习。核对本次参数，必要时调整，之后领取开仓、识别并开始。STM32 负责单次摆药内调速；舵机取值 0–1，数值越小开口越大。模拟参数不用于实机，不迁移旧学习数据。
6. 观察计数与 FINISH、暂停恢复、同盘下一药与换盘识别。只有确认可投料的阶段才显示投料提示。参数 ACK 表示已接收，不表示实测角度或机械位置。
7. 每台实机都按同一顺序验收：最终开仓完成后取出药盒，确认收到匹配当前长者条码的 `DISAPPEARED`、取盒提醒消失、轨道收回，并在收仓 ACK 和 DONE 齐全后释放任务。

自动学习的软件验证见 [Android 验证报告](validation/2026-10-27-android.md)；真实设备上的动作和学习效果仍待验证。每份处方药物条目独立保存、版本冲突保护和形态变化处理仍按 [R14](02-workflows-and-rules.md#r14-每份处方独立的出药参数)执行。

## 中断与退出

- 暂停/继续不会重发数量矩阵。断联重连只连接原端口，不自动恢复；只有确认机器未复位、原药盒/药物及进度仍保留，才选择继续。已观察到复位时阻止直接继续。
- 关闭窗口会进入受控停止路径并留在软件中。待停止应答后，确认机器安全停稳且药盒和剩余药物处理好，再结束并同步；之后可退出。系统强杀或断电不等于已经发送停止命令。
- “结束此次分药（不记录）”只在现场已经安全处理后使用：删除本次关联数据，不发送开仓、收仓或停止命令；网络未恢复时保留删除意图并锁住本机。
- `.var/terminal-sjtu` 保存终端身份、任务、原始反馈和待同步事件。任务未结束时不要清空、复制到另一台终端或替换该目录。
- 无法确认在轨/离轨/就绪时保留占用。当前没有用人工“已取出”按钮强行完成的旁路。

已运行证据与未完成范围见 [执行验证报告](validation/2026-10-26-execution.md)。
