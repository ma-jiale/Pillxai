# 设备失联、命令应答与堵转提醒

目标：中止失联任务并提醒重启分药机；区分普通 ACK 重试、解除堵转、DONE 超时和初次连接失败；收到堵转后立即提醒工作人员。

已实现 Android EOF、读写 IOException、连接期间蓝牙关闭的分类上报，以及普通命令最多六次发送、每次等待 ACK 0.2 秒。收到首个 ACK 停止重试，需要 DONE 的命令另起动作等待，默认 10 秒；DONE 超时保留连接和接收。主动断开、初次打开或初始接收失败、扫描失败不进入统一失联弹窗。单纯静默不判失联，未新增心跳。

失联清理意图与提醒持久化；在线时清理服务器任务，离线时保留清理请求并重试，不能恢复原任务。固定提醒确认后关闭旧确认窗口、刷新资料并回首页，不自动重连。离线待清理任务仍保留内部快照和队列，不能续摆。

`stalled:N` 与 `stallN` 都解析电机编号，自动弹窗覆盖开仓、执行与空闲接收。勾选框“解除堵转”默认勾选，点击“确定”才发送一次；取消勾选只确认提醒，不发送命令、不清除故障。已确认的 2/3 号电机可以解除，其他编号仅提醒。多个电机分别处理，同一未处理报告合并；提醒跨页面、后台和重启保留。缺 ACK 保留连接与接收，解除期间新堵转使旧 ACK 失效，解除后不自动续摆。开仓仍跟踪 ACK/DONE，未解除时阻止新批次及自动收仓。

验证：执行模块 105 项、客户端 141 项、API 90 项、协议 6 项通过。包含精确重试边界、迟到反馈不复活任务、单次解除、不勾选不发送、多电机与通知恢复、跨页自动弹窗、默认勾选和确认回首页。客户端静态检查无问题；后端 lint 与生成契约检查通过。执行模块仍有既有 `terminal_session_test.dart:64` 花括号提示，API 仍有既有 Starlette/httpx 弃用提示。

Android Debug `0.2.6-dev / 8` 构建成功，已保留数据覆盖安装实体测试平板的独立开发包 `com.pillxai.pillxai_client.development`，版本通过设备包管理器核对，正式包未覆盖。本机 8001 API 已更新并通过 ready 检查，USB 为平板 8000 转发电脑 8001。安装等待设备端确认期间，未完成的旧版安装会话已取消；最终包安装成功。
