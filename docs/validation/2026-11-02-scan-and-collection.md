# 扫码摆药与完成取盒提醒

## 用户目标与输入

移除摆药页下方三点菜单及其设备、结束入口，以跳过处理剩余药物。完成一位长者的任务后弹窗提醒取盒，不能手动关闭。首页新增“为任意长者摆药”，按开仓、扫描药盒、核对长者和药物、确认启动的顺序工作。

复用已确认的开仓/收仓 ACK、DONE 协议、条码 APPEARED/DISAPPEARED、长者条码查询和计划/任务接口，不读取旧实现、不增加设备命令。

## 实现

- 正式及演示执行页移除三点菜单；删除演示菜单专用计划弹窗与取消处理。设备管理、受控退出、断联清理的共用逻辑保留。
- 正式工作区在任务进入取盒阶段后显示长者姓名、床位与完成提示；有跳过时使用任务结束、部分药物跳过的文案。弹窗无关闭按钮，返回和空白点击无效；有效离轨反馈自动关闭，断联提醒优先接管。收仓与同步仍由运行模块完成。
- 新扫码入口先开仓再查询当前条码对应的长者，复用计划核对界面；用户确认后领取并取得启动许可。运行模块保留本次开仓与识别结果，不再发送第二次开仓。接收中的取盒反馈在领取挂接、启动前再次处理，不能用旧识别启动。
- 未知标签、查询失败、取出/更换药盒均不能沿用旧核对结果。识别会话持久化；宿主重启进入待核对，不自动重发。关闭空会话需明确操作并等待收仓，已有药盒时拒绝关闭。
- 本轮没有新增或改动 HTTP 契约；扫码入口按已绑定长者条码工作，RFID 仍参与任务挂接后的既有冲突与身份检查。

## 验证

- 客户端 146 项测试通过，含正式界面完整流程、未知标签、移走药盒、核对后启动、空扫描会话收仓、取盒弹窗阻止返回及断联接管。
- 运行模块完整回归 109 项通过，随后新增的启动许可请求期间取盒测试亦通过；扫码专项共 5 项通过，含一次开仓、许可前不下发矩阵、领取期间移走药盒、匹配消失才允许关闭、识别中断恢复。
- 菜单移除的截图基准仅变更三点图标的 51 个像素，已核对并通过视觉回归。
- 测试使用模拟传输与 HTTP 替身；本轮尚未进行真实机器开仓扫码、实际取盒反馈与平板后台验收。构建成功不代表实机通过。
- Android Debug `0.2.7-dev` / `9` 构建通过，包名为 `com.pillxai.pillxai_client.development`；APK 位于 `apps/client/build/app/outputs/flutter-apk/app-debug.apk`。
- 用户随后要求安装实测，已通过 USB 在 BTKR-W00 上保留数据覆盖安装并打开开发版；ADB 返回 Success，核验版本为 `0.2.7-dev` / `9`。安装前本机活动任务、待上传事件均为 0，无领取请求或识别会话；测试 API 8001 健康检查通过，平板 8000 经 USB 转发到电脑 8001。未触发连接分药机、开仓或摆药动作，实机流程仍待用户测试。
