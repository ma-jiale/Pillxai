# 当前药报错后的弹盒核对

对应 R11、P08 和 A30。输入为已启动批次的 STM32 报文 `machine_state:CNT_ERR`。

- 执行宿主保存报错、停转、退出和开仓反馈。正式工作区自动显示核对弹窗。开仓完成后按本盘的日期、时段与机器位置映射展示本药目标，确认前保留原批次。
- 同盘有下一药时要求药盒识别匹配。跨盘还须观察到本盘取出，再识别放入的药盒，由工作人员核对下一盘用途。最后一药复用已打开的药仓，按有效取盒证据收仓。
- 人工确认沿用本盘整批人工结果，事件携带 `source=counter_review`。服务端校验原始报错与停转、退出、开仓的应答顺序。已确认范围与原始累计计数分别留存，异常批次不生成学习值。发布顺序为服务端、客户端，旧服务端会拒绝该来源的结果。

## 实际验证

- 本机执行模拟覆盖重复报错、迟到 FINISH、缺少退出 DONE、重启阻止续摆、核对期间堵转、错盒、跨盘重识别、重复确认，以及最后一药确认前后取盒。
- Flutter 正式入口验证机器报错自动弹窗、开仓完成前不提供确认、未满足条件时按钮禁用，以及确认后切换下一药或进入取盒。
- FastAPI 与项目 PostgreSQL 测试库验证分段补传、缺少开仓完成反馈时拒绝确认、人工结果保留原计数、补传幂等和最终收仓。
- 学校服务器已部署 `76211460235aee06526db67cb402caebe4417337`，[V2 发布流水线](https://github.com/ma-jiale/Pillxai/actions/runs/41616767873) 的 test、package、deploy 全部成功。[公网就绪接口](https://ixd.sjtu.edu.cn/pillxai/health/ready) 返回 ready 与对应提交版本。
- 服务器就绪后，已通过 ADB 在 BTKR-W00 上保留数据覆盖安装并启动「Pillxai 开发」`0.2.10-dev`（12），包名 `com.pillxai.pillxai_client.development`，API 指向学校 HTTPS 地址。ADB 已核实版本和启动结果。更正：安装前的空闲检查读取了旧开发目录 `terminal`，不能据此证明学校目录当时的活动任务数和待上传数。本次实测核对读取学校目录 `no_backup/terminal-sjtu/execution.sqlite` 及 WAL。
