# V1 空舱取消收仓修复

日期：2026-10-29。范围为用户明确授权的 V1 空舱取消问题，不修改新版 Flutter 实现或现有未提交改动。

## 用户目标与原因

开舱后没放过药盒，点击关闭直接收仓；放过药盒保留取盒检查。原取消入口无条件等待取盒；检查器在没有历史在位观察时不通过，直到 120 秒超时才显示人工确认，期间取消按钮隐藏。

## 修改

- V1 `PillBoxUnionChecker` 暴露 `CanCancelWithoutRemoval`：仅允许有效等待放盒会话、存在可用通道、无历史在位观察、当前所有通道均未报告在位。历史在位不会因取出或身份验证失败而清空，只在会话结束时重置。
- V1 `UIManager` 在准备阶段取消且没有失联提示时使用该判断，直接进入现有收仓方法；收仓失败仍提供重试。
- 已放盒、错盒、取出后再取消仍使用原取盒等待；分药完成不使用空舱快捷分支。平板摄像头解码静默仍不作为取出证据。

## 待实机验证

1. 开舱后不放盒，点击关闭：应立即发起收仓，成功后回首页。
2. 放入可识别药盒后点击关闭：应保持开舱，取出且满足原稳定检查后收仓。
3. 放入再取出后点击关闭：仍经过原取盒检查；再次放入应阻止收仓。
4. 收仓失败应保留重试，不能当作已回收成功。

软件通过识别通道观察放盒；无法识别的实体物体不能由此测试判定为空舱。
