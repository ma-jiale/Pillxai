# 2026-10-29 Android 应用更新验证

目标：在 `feat/ota-client` 为 V2 Android 提供自动检查、空闲时自动下载、人工确认安装；安装与执行任务互斥，覆盖升级保留本机数据。依据为当前 R15/N04 和独立执行宿主，不参考旧客户端实现。

## 本轮交付

- FastAPI 权威发布模型、只读清单与 APK 接口，生成的 OpenAPI/Dart SDK；无发布、撤回和异常发布状态明确区分。
- Flutter 工作区持有更新控制器；设置提供真实版本、持久化自动下载开关、说明、进度和安装操作。
- Android HTTPS 下载、大小/哈希/身份/版本/签名校验、未知来源授权、PackageInstaller 系统确认、取消与重启恢复。
- 执行队列持久化更新锁，拒绝任务/领取/药盒未取出/非空闲/待补传等状态进入安装；锁期间禁止领取、设备动作与服务退出。
- 正式签名配置、手动触发的构建工作流、原子发布工具、服务器发布目录只读挂载及运维说明。

原生 APK 校验/取消/覆盖恢复使用调试测试包。执行保护最后增加“空闲但药盒仍在”的拒绝条件，已另由执行模块测试验证。

## 同日补充：只分发正式版

用户进一步明确日常只使用正式版，新增以下约束与验证：

- Android 发布工作流只运行 `main`；版本名只接受 `主.次.修订`。actionlint 通过；GitHub Environment 的 `main` 分支保护仍需实际配置。
- 正式包启用 `PILLXAI_ALLOW_DEBUG_SIGNING=true` 或 `PILLXAI_DEMO=true` 的 Release 构建均实际验证被拒绝。测试签名开关仅对独立 runtimecheck 生效。
- 普通 Debug/Profile 改为 `.development`，名称“Pillxai 开发”；runtimecheck 名称“Pillxai 测试”。重新构建 Debug，并通过 `aapt dump badging` 确认实际 APK 包名和名称；不占用正式应用身份。
- `run-android.ps1` 只向已核对的模拟器安装开发包。实体设备 ID 拒绝路径及 PowerShell 语法检查通过。
- 发布工具删除调试放行开关，拒绝调试签名、可调试 APK、开发/测试包名及预发布版本。发布工具 8 项测试通过（包括新增 5 项身份/版本验证）；相关 Ruff 检查通过。

本阶段未执行实际发布。历史测试报告中的 Debug 实机联调是当时证据，不作为当前交付方式；后续正式签名配置见下节。

## 同日补充：正式签名与 GitHub 环境

按用户进一步授权生成正式 RSA 4096 / PKCS12 密钥，保存在 Git 忽略且受 ACL 保护的 `.signing/android-release/`；密码使用当前 Windows 用户 DPAPI 加密。GitHub `android-client-release` 实际配置为仅 `main`，四项签名 Secrets 和公开证书指纹变量已保存并重新加载核对。

本地正式签名 Release 构建通过（0.2.0 / 2，通用 APK 84.6 MB）。首次验签命令缺少 Java 运行时配置；使用与构建一致的 Java 路径后，APK 签名 v2 验证通过，单一签名者的 SHA-256 与正式记录一致。该功能分支制品仅用于验证，未发布或安装。发布工具增加证书指纹校验，11 项发布工具测试和 Ruff 通过；工作流 actionlint 通过。证书与保管记录见 [正式签名配置](../../deploy/android-client/signing.md)。
