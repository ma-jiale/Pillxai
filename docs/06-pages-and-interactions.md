# Pillxai Dispenser 页面与操作流程

本文件把业务规则落到工作人员可操作的页面。权限见 01，默认值见 00，状态与计算以 02 为准。2026-10-27 用户明确否定接入后台后的 UI 还原效果：已确认的新版 Flutter 页面、组件及其渲染截图作为复原依据，业务接入不能另写一套近似页面而改变比例、布局和交互层级。尚未定义的新状态沿用同一套视觉组件，并以完整正式入口验证。首发 Flutter Android 平板，优先触控操作与平板可读性；后续手机、Windows 及 iOS 按屏幕与输入方式调整布局，沿用相同业务含义和允许动作。设备控制入口按客户端实际连接能力提供，不能因为页面可复用就假定平台已具备机器控制能力。

应用名称为 Pillxai Dispenser，现有[方形主标志](../assets/branding/pillxa-mark-rounded.png)和[文字标志](../assets/branding/pillxa-wordmark.svg)保留为品牌参考。用户最新要求移除 Pillxai 图像 Logo，左上角、登录页和加载页仅保留 `Pillxai` 文字字标；品牌区沿用已确认的极简风格。用户要求 UI 现代、简洁、有高级感。用户提供的原型值得借鉴，尤其是围绕当前药物、进度、下一药预告和放取盒图解组织工作的方式；其他视觉参考按本轮指定范围使用，不逐项照搬。

**当前风格状态，2026-10-18**：用户已确认当前极简版为唯一界面，移除底部方案切换栏和其他方案，继续完善处方管理。保留低信息密度、当前药物大图、清楚进度和三个入口侧边栏。主体采用白色或浅灰背景，允许灰色主背景配白色卡片，灰色用于区分层级。黑色仅为默认强调色，可由用户个性化调整；药品图片保留原本色彩。[组件风格参考](../assets/ui-references/06-UI组件风格参考.png)仅借鉴细边框卡片、胶囊按钮与轻巧图标；[平板比例参考](../assets/ui-references/05-平板比例参考-不参考配色和结构.png)只用于文字、图标与控件的尺寸比例，不借鉴其配色、信息密度或 UI 结构。[横向侧栏参考](../assets/ui-references/16-横向侧栏与灰色选中态.png)用于导航的图标文字横排、较长圆角矩形和固定浅灰选中态。始终突出当前药物和进度、保留简短下一药预告与左上角品牌区。“处方管理”“摆药”“设置”直接切换，不增加返回页或全局返回按钮。用户原型与参考图保留在 [UI 参考目录](../assets/ui-references/index.html)，不再展示其他候选方案。默认三个模块已接入真实服务，Windows 执行及 Android 前台服务的模拟器流程已通过；内存演示仅在显式构建中启用，实体平板和真实 HC-06 仍待验收。运行入口、实际验证结果和当前限制见[客户端说明](../apps/client/README.md)。本文件后续章节描述生产功能和进入条件，不要求所有信息同屏出现，也不表示这些功能已在预览中完成。

比例调整先缩减标题、普通文字、图标与控件的可见尺寸，保持进度相对突出和信息层级清楚；释放出的空间用于留白，不补入更多常驻信息。比例参考仅用于判断文字、控件和画布之间的相对尺度，不引入其深色配色、复杂信息密度或结构。生成图的像素不作为应用逻辑尺寸，具体字号、间距与控件比例须在目标平板的实际逻辑尺寸、显示缩放和现场观看距离下验证。视觉上的轻巧不缩小必要触控区域；仍需验证正常及放大字体下的可读性、内容完整性与触控操作，不把整张图等比缩小作为实现方案。

切换页面、其他应用和锁屏时摆药继续，回到应用显示最新真实状态。主动关闭通过“结束本次并退出”进入 R12 的受控停止和现场确认，取消本次且不计完成覆盖；彻底删除与普通关闭的关系待确认。系统强杀或崩溃进入异常恢复，不把窗口关闭或进程消失显示为机器已停止。

## 浮层与控件的一致性

UI 复原由正式数据与演示数据共用展示组件：工作区顶栏与设备状态按钮、清单行、准备确认外框与用药表、执行身份区与当前药/下一药卡片、主操作按钮、取盒状态条。数据查询、权限、识别与任务推进分别由对应控制器提供；展示组件不导入演示模型或设备运行时。准备确认在开仓后保留原弹窗并订阅真实识别，匹配后才允许确认开始；准备阶段“关闭”按 R06 检查取盒并收仓取消；有盒时保留弹窗及任务，本次开仓完成后从未观察到药盒也允许明确关闭收仓，不显示执行药物卡片。领取后锁定本次计划，后续资料变化不重写它。

还原验收直接挂载正式 `PillxaiApp → ConnectedWorkspace`，经登录、七药核对、识别、执行、暂停、换药、换盘、取盒完成全流程。仅检查控件存在、无溢出或简化外壳截图不代表视觉一致；需同时保留已确认截图、同尺寸正式截图、动画关键帧和目标平板实测。原确认版金图不能因新实现不匹配而自动更新。当前工作记录及仍未完成项见 [UI 复原记录](validation/2026-10-27-ui-restoration.md)。

展开态与页面使用同一套白灰视觉语言。选择器与操作菜单采用锚定控件的小浮层、细灰边框、轻阴影、16 像素圆角和浅灰选中行；选择项显示勾选标记，触控行高至少 48 逻辑像素。账户菜单在头像附近展示当前身份、设置与退出操作，靠近屏幕边缘时自动避让。设置、处方和摆药复用同一套菜单组件；确认弹窗、日期选择器、开关及提示统一通过主题控制，去掉默认水波纹与表面染色。键盘操作、Escape 关闭、点击外部关闭、窄屏完整显示均须验证。

## 侧边栏与模块归属

处方管理和设置页不显示未结束任务的提示条；工作人员通过侧栏“摆药”查看当前任务。切换模块仍保留任务状态。

2026-10-30 用户确认：主侧栏只保留“摆药”“处方管理”，登录后默认显示摆药；“设置”移到左下角账户菜单，在“退出当前用户”上方使用齿轮图标。展开侧栏采用图标与中文名称横排、较长的圆角矩形；选中背景固定为浅灰色，不随用户强调色变化。“摆药”使用下半黑色、上半白色的胶囊图标，“处方管理”保留原图标。模块切换直接显示对应内容，不设置独立返回页、全局返回按钮或“返回工作空间”步骤。

侧栏右上角提供“收起侧栏 / 展开侧栏”按钮。宽屏展开宽度为 232，收起为 76 逻辑像素；收起后隐藏品牌文字、导航文字与账户名称，只显示导航图标和头像，图标提供文字提示与无障碍名称。折叠选择在当前工作区会话内保持，切换页面或强调色不重置，也不改变任务与设置草稿。窄于 600 逻辑像素时默认图标侧栏，展开以浮层覆盖内容，不挤压业务页面；点击遮罩或选择模块后收起。

左下角固定显示当前账户的圆形头像与名称，收起时仅显示头像。点击打开锚定账户入口的浮层，展示当前姓名、角色，以及“设置”“退出当前用户”。当前账户入口使用正常业务文案，退出后回到登录页并清空账号和密码，已接入真实服务身份认证；有正在执行、暂停或待换药的任务时，提示先完成或结束当前摆药，不能通过退出账户丢失任务。正式账户注销与本机执行交接仍需按 R12 实现和验证。长者示例头像采用带柔和色彩的简笔画，资料列表与详情保持一致。加载页只保留 Pillxai 文字字标，移除“正在准备工作空间”文案。

| 导航入口 | 模块内的能力 |
| --- | --- |
| 处方管理 | 长者资料、处方编辑、药盒绑定、标签导出、处方参数；长者详情可查询其摆药历史 |
| 摆药 | 今日待摆清单、计划核对、药盒识别、当前执行、换盘、取盒与结果；历史记录由模块内入口查询 |
| 账户菜单 → 设置 | 通用、外观、关于；应用规则、账号与权限、版本和支持信息按角色显示可用内容 |

长者、记录、今日工作不另设第四个顶级入口。执行中的参考图选中“摆药”；进入“处方管理”或“设置”仅切换显示，不暂停、重启或取消当前任务。本机执行状态独立保存，切回时展示最新真实进度，切离时保留精简任务状态条。

处方或应用设置有未保存修改时，切换入口不得静默丢失输入；提供保存后切换、放弃修改并切换、继续编辑，保存失败保留输入和当前页面。这是对未保存内容的保护，不是日常导航中的返回步骤。

## 信息层级与持续可见的信息

三个顶级页面及执行页的主标题保持相同字号与顶部坐标，正文不重复显示主标题；摆药和处方管理使用工作区顶栏，执行中标题改为“正在分药”。移除页面标题下的说明小标题与待摆清单顶部日期，保留业务条目说明及设置分组名称。设备状态按钮仅在摆药顶栏右侧显示。设置页的“设置”标题只占左侧分类栏顶部，与主侧边栏、分类栏统一使用浅灰色；右侧不设顶栏，白色设置内容区直接延伸至顶部。窄屏单列布局保留顶部设置标题。长者列表、详情、准备确认与执行页复用圆形头像和姓名床位组件，同一长者保持同一头像；没有头像时统一显示通用人像。准备弹窗的天数选择器沿用其他页面的公共选择器样式，预览按钮与用药表头之间保留明确留白。七药列表提供可见滚动提示，滚动不移动核验状态或开始按钮。

界面统一使用“长者”称谓，列表、搜索、表单、操作结果和空状态文案保持一致。

以处方管理原有的白色细边框卡片为统一依据：白底、16 像素圆角、浅灰细边框，无投影；标准内容留白为 24 像素，长者侧列表为 16 像素。处方管理保留原有长者列表和资料卡片；摆药待准备/提前准备的长者清单、当前药与下一药均使用同一容器，列表内用细分隔线组织。当前药通过图片和进度的尺寸突出，下一药通过更小的卡片和文字降低层级，不另设浅灰卡片方案。卡片接替动画保留，药品图片保持原色。

正常执行时，让工作人员一眼看清“正在为谁摆哪种药、摆到多少、如何暂停”。主区域聚焦长者、当前药物图片/名称/规格/投料形态、进度与暂停；盘用途和当前阶段使用简短上下文。完整计划、历史处理摘要、设备资料和同步诊断按需查看，不与当前操作争夺注意力。下一药只作简短预告，到换药阶段再展开为主内容。

人员和本机连接信息使用紧凑的环境入口，完整内容在账号或设备面板展开；发生登录失效、断联或其他会影响当前操作的变化时，直接说明影响与下一步。切离执行页后保留精简任务状态条，显示长者、当前药物和进度，点击返回执行台。版本、检查更新、自动下载更新开关与支持信息在设置的“关于”中可查。

按阶段展示操作：准备时核对，执行时看进度，换药时看下一药，放取盒时看简短图解，异常时看处理步骤。渐进呈现不能隐藏影响身份、剂量、投料形态或是否允许继续的关键条件；异常应立即出现，当前必需的处理按钮直接可见。参数调整保留执行台的一步入口，无需离开任务或进入多层设置。

每个列表区分读取中、空结果、失败与成功；每次保存区分保存中、已保存和失败。失败保留已输入内容。弹窗和快捷键作用于当前设备任务，不改变其他终端。

页面切换不改变本机任务归属。正在执行时可查资料，保留任务状态条；更新和退出执行相关处理不能藏在无提示的页面跳转里。图解和插画用于帮助理解当前动作，不增加与工作无关的装饰卡片或统计模块；留白、字号层级和黑白明暗对比共同建立视觉重点。

仅“摆药”界面右上角显示设备连接按钮，“处方管理”和“设置”不显示该按钮；切页不改变连接状态。按钮使用按实物前脸绘制的摆药机矢量图标与“未连接 / 已连接”，统一代表蓝牙、USB 串口。所有显示尺寸均使用最初的简洁机壳、双孔、料斗弧线与托盘轮廓，不使用蓝牙图标。点击打开“我的设备”大面板，关闭后保留原页面。面板顶部左侧标题及开机提示，设备横向排列：左侧机型图标、中间名称及状态/连接方式、右侧连接/断开与移除；底部固定“添加新设备”。不新增侧栏入口。搜索在同一面板内切换，上方返回与关闭，中央机型图标、开机及蓝牙靠近/USB 插线提示，下方列出候选设备；底部重新搜索。保持白灰配色、细边框及圆角，不照搬参考图的品牌色或打印机开机操作。

正式客户端的“我的设备”只突出设备名称、连接状态与连接/断开；地址、协议、映射、原始反馈收进维护配置，不在日常列表展开。Android 点击“添加新设备”搜索附近尚未添加的摆药机，包含未配对设备；已确认的蓝牙名称前缀 `PillDispenser` / `dispenser` 用于发现候选，稳定地址用于身份绑定，通用 HC-06 名称不能自动证明是摆药机。点击“添加”直接尝试配对，默认码 `1234`；系统要求确认时提示确认，成功后保存设备并自动连接、返回“我的设备”。配对失败不登记，保存失败不连接；连接失败保留已保存设备供重试。新设备不继承旧设备的已验证映射或取盒规则。Windows 仍使用明确的串口维护配置。实体映射入口保留在“设置 → 通用 → 药盒布局 → 设置映射”；保存映射不发机器命令。活跃任务锁定搜索、配对、配置和断开操作。服务端设备删除尚未提供，正式行的次操作是维护配置，不提供假移除。工程模拟选项仍仅在展开的配置内，实际任务明确标注模拟演练。

## P01 登录与账号管理

**用户最新要求，2026-10-26**：当前客户端不需要账号管理界面，已移除临时管理页面与入口；保留登录、退出及服务端认证和权限接口。下表的账号管理与改密交互为后续候选，不作为当前页面交付要求。

登录页沿用白灰配色、左上角 Pillxai 品牌与简洁居中表单，提供账号、密码、密码显隐及登录按钮。登录成功后直接进入摆药待准备清单，无机构选择或创建入口。窄屏及软键盘弹出时可滚动操作。账号由管理员分配，不提供自行注册。

当前默认入口使用真实服务认证，随机开发凭据见客户端 README。账号与会话只留在进程内存，刷新后重新登录；服务端注销、停用及改密会撤销会话。显式演示构建的本地账号不具备服务端权限。安全持久化和会话恢复仍未实现。

| 步骤 | 信息与操作 | 完成条件 |
| --- | --- | --- |
| 登录 | 账号、密码，“登录” | 直接显示摆药待准备清单 |
| 添加账号 | 显示名称、用户名、初始密码、角色、维护权限 | 管理员保存成功后账号可用；用户名冲突明确提示 |
| 账号管理 | 状态、权限，“编辑”“重置密码”“停用/恢复” | 服务端执行权限检查；历史操作人保留；禁止通过管理接口更改自己 |
| 修改本人密码 | 原密码、新密码 | 核对成功后撤销已有会话，重新登录 |

工作人员不显示账号管理；服务端同样拒绝管理接口，不能仅靠隐藏按钮限制权限。

## P02 待摆清单与长者资料

“摆药”模块内的准备清单只保留“待准备”和“提前准备”，支持姓名/床位搜索，不设置“全部长者”页面，不展示当前任务或院内进行中任务区域。提醒和计划由中央按 R01 生成，模拟记录不计入实际覆盖。读取失败显示失败，不用零人数代替。每位长者的行按钮为“开始摆药”，点击打开 P05 的信息确认弹窗；本机已有未结束任务时，切回“摆药”直接显示该任务原有阶段，不经过清单重新选择。

清单默认突出姓名、床位、简短的待准备原因和开始动作；已有覆盖和本次建议日期作为必要的辅助信息，其余内容在确认弹窗内核对。任务归属冲突在领取时明确提示，不增加常驻的机器状态卡片。全部已登记长者在“处方管理”查看。当前内存预览中，有效日期内存在布局或剂量校验问题的长者仍保留在清单并显示原因，不能以“无需准备”隐藏；已经结束或本周期尚未开始的药不参与本次布局校验。

“处方管理”模块内以统一列表展示全部已登记长者，支持姓名/床位搜索、“添加长者”“导出标签”。搜索后，右侧详情只能展示当前列表内的长者。详情分为当前用药、资料与药盒、摆药历史；用药使用紧凑条目排列，突出药名规格、时段剂量、餐食要求和疗程。已停止用药可展开，出药设置放在有权限人员的更多操作中，版本不占日常列表。长者保存后直接可进入处方维护，不必先连摆药机。平板宽屏下名单与详情独立滚动，搜索及添加入口固定可达；点选后详情回到顶部。窄屏或可用高度不足时纵向排列，点选后定位到详情，不让长名单把所选资料推离可见区域。处方管理不展示“摆药准备”栏或准备、开始摆药的快捷入口；工作人员从左侧“摆药”模块进入准备清单并开始摆药。

资料表单：姓名、完整床位文本、照片；自动编号只读。空床位允许保存，非空床位在本院全部已登记长者中查重，冲突定位到另一长者。

## P03 处方编辑

逐条显示药名、规格、图片、各启用时段数量、餐食关系、起止期间及状态。提供“新增药物”“保存修改”“停止用药”和历史版本。

选择整片或预切半片后，输入和预览明确区分原片用量与机器颗粒。未启用睡前时不显示可执行睡前格；若历史条目已有该时段需求，先解决布局，不静默忽略。

表单依次组织药物信息、每次用量、用药期间，图片可选，长期和有限疗程明确选择。切换整片/半片时保留原用量，形态不匹配时定位提示并阻止保存，不能自动改写剂量。当前预览的表单与计划共用剂量校验纯函数，数值保护范围不作为临床用量或硬件容量依据。保存前显示具体校验错误；保存失败保留输入。半片改整片、药物或规格改变时提示“出药设置待调整”，其他处方参数不受影响。普通改日期或时段不会强制重新学习。

## P04 标签导出

勾选长者，输入每人份数，显示总张数、A4 页数；生成成功后在应用内显示按页排列的标签预览，包括姓名、床位和实际身份条码，预览与导出共用标签身份及版式定义。无需依赖客户端的 PDF 内嵌阅读能力。点击“导出 PDF”保存文件，实际打印尺寸以 PDF 为准。生成期间固定选择对象和份数，失败保留选择；没有打印机或精臣服务也可导出。

条码内容用于长者身份识别，版面显示姓名和床位。生成成功仅表示文件成功，打印由常规 PDF 工具完成。

## P05 摆药信息确认弹窗

点击清单行的“开始摆药”后，在独立弹窗用文字核对所选长者、床位、覆盖日期、本次天数、药物和盘用途。长者信息、日期与天数、药物清单分区排列；药名规格、投料形态及数量对齐，留出清楚间距，不在确认信息中混入圆点图案。弹窗提供本次分发天数选择，默认 7 天，允许 1–7 天，不要求每次修改；本次选择不修改长期应用设置。覆盖起点仍按已有覆盖及应用规则自动计算，不提供手选起点。调整天数重新生成并校验未开始计划，更新覆盖日期、数量和图案；等待校验期间禁用开始按钮，不改已开始任务，不重复领取或重新开仓。当前正式界面先核对计划，点击“开仓放入药盒”后领取并保存任务、请求机器开仓；识别成功后再确认开始。这样本次天数仍可在开仓前调整，不重新开仓或修改已领取快照。药盒绑定和独立参数收在“药盒与出药设置”，正常摆药无需经过该维护页。

药物清单按 7 种及更多药物设计容量：头部长者身份、天数与覆盖日期固定可见，底部药盒核验状态及取消、开始操作固定可见，中部清单独立纵向滚动。标题显示药物总数；每种药占一行，药名、规格和投料形态完整换行，时段用量及数量列对齐，不截断长名称，不横排堆叠药物卡片，不因药多缩小文字或默认折叠药物。短屏、窄屏及放大字体时仍能滚动浏览所有药物，身份、核验状态和操作不能被清单推离可操作区域。

“预览摆药图案”按钮打开独立预览界面，按盘用途查看日期列、服药时段行的药格图案。每种药物使用一种颜色的圆形，圆点不带字母，圆点数表示该格计划颗粒数；颜色只用于区分药物，不代表药粒实际颜色。当前预览每格最多绘制24颗圆点；超出时显示精确数量摘要，点按可读逐药数量。此显示预算不改变计划，不表示硬件容量，也不把剩余数量隐藏为已完成。图案旁配药名、规格及整片/半片投料形态文字图例，点击药格可查看每种药的文字数量，不靠颜色单独识别。同名不同规格分别标识，半片的一颗圆点表示一颗人工预切半片，原片等价量另列；总颗数和原片等价量与计划一致，不以 mg 作为圆点数量。图案明确标为“计划”，不能当作逐格实测或完成证据。日期显示月日及星期，星期不能代替日历日期；横向滚动时固定时段列。有限疗程只显示有效用药范围，不因选择 7 天额外生成用药；未用位置为零。关闭预览回到原确认弹窗，保留已选天数、任务归属及药盒核验状态，不重复领取或开仓；预览期间收到取出或更换药盒等新反馈仍按 P06 更新核验，不能恢复过期匹配。覆盖起点沿用应用规则，本次分盘开关保留，不把这些详情常驻铺满确认弹窗。

预览界面文字精简，只保留日期/时段、药名规格与形态图例、必要数量；不放说明段落或解释卡片。关闭按钮使用点缀色，姓名后的圆点移除并保留原有日期起点。各药文字数量在点击药格后显示，不逐格常驻铺开；计划、颗粒与原片等价量的业务含义仍按上述规则保存和展示，不把文档解释全文放进界面。

图案预览使用较大的独立弹窗；药物超过 7 种或同格颗粒较多时仍保留日期与时段定位。格内按图例中的固定药物顺序排列圆点，同一药物相邻，空间不足自动换行；圆点保持可辨大小，不以缩小圆点、截断或“+N”代替未显示药粒。各时段行高随内容增大，矩阵可纵向滚动；横向滚动时固定时段列，纵向滚动时保留日期标题。宽屏在矩阵旁以单列图例展示全部药物，窄屏将图例移至矩阵下方，长药名、规格和投料形态完整换行，可滚动查看全部条目。每药颜色在当前计划、各盘和图例中一致，选用有足够差异的颜色；点击图例突出对应药物，其他药物圆点仍保留并变淡，不改变计划或隐藏数量。点格文字明细仍可核对全部药物，不依靠颜色单独辨识，不为容量增加额外说明段落。

药盒识别、匹配失败、关闭检查及操作失败统一显示在弹窗底部同一个浅灰矩形状态框内；错误替换当前提示，不在框外另起一行报错。此规则由用户于 2026-10-28 确认。

弹窗操作：

- “开始摆药”：下位机本次检测的药盒 ID 匹配当前长者，并满足 P06 的全部开始条件后可用；确认后直接进入正在分药界面，不再增加一次开始点击。
- “关闭”：尚未领取时直接关闭；已领取但未开始时按 R06 检查轨道。有盒时提示取出后再点击；本次开仓完成后从未观察到药盒或已有本次取盒证据时才收仓，断联或恢复后的未知现场进入核对，ACK、DONE 后取消准备并回清单。弹窗外点击和系统返回不能绕过关闭检查。
- 需要改处方时可切到“处方管理”并定位当前长者，未开始任务按 R04 重新校验，不通过离开弹窗释放任务或复用旧计划。

处方或布局变化显示“计划已变化，请重新核对”，在弹窗中重新生成确认；没有待摆药物显示原因。任务已被其他终端领取时显示设备与人员，不发送设备动作，不让工作人员反复尝试下发。

## P06 识别与首次开始

从准备清单选择长者，核对计划后点击“开仓放入药盒”，执行“领取任务 → 保存本机任务 → 请求开仓”。只有联网、计划有效、本机空闲且任务归属成功后才发送开仓请求；领取失败不发送设备动作。开仓结果未知时保留已领取任务并进入现场核对，不盲重发。未连接机器时打开“我的设备”连接。请求成功后显示“请放入这位长者的药盒”，等待下位机在本次识别会话中检测并上报的药盒 ID，不增加来源选择、扫码输入或再次点击扫描。此处定义业务等待条件，不新增或推定硬件协议字段。

弹窗只展示未连接、开仓中、等待放盒、核验通过或需更换药盒等当前状态；匹配成功显示姓名与床位。没有人工指定长者或“模拟反馈”选择器，测试通过组件外注入识别状态验证。无法收到有效 ID 时保留任务，生产设备适配提供重试能力；当前未接入设备时如实显示未连接并禁用开始，不伪造开仓或匹配。开仓和识别会话状态由本机保存，弹窗重绘、重新显示及页面重载不重复下发开仓命令。

放盒阶段借鉴原型的图解表达：以与实际设备相符的放盒示意、一个动作提示和当前核验结果为主。图解只在需要放盒、换盘或取盒时出现，核验完成进入摆药后让位于当前药物；不同时堆叠所有阶段说明。实际放置方向须经设备事实确认，不能由示意图推定。

下位机本次检测的药盒 ID 匹配所选长者、计划有效、归属已确认、本机就绪且完整资料已在本地保存后，弹窗“开始摆药”才可用。点击后按 R04 保存启动意图并确认归属，再执行首药并直接进入正在分药界面。启动前新发现版本变化在弹窗重新生成并核对；断网时说明等待网络恢复，不能离线首次开始。

不匹配保留当前任务长者，提示“请更换为〔长者姓名〕的药盒”，禁用开始按钮；未绑定标识提示到长者资料完成绑定，并展示具体标识和“复制标识”按钮。RFID 显示可直接用于绑定的完整十六进制 UID，保留前导零，不包含 `UID:` 前缀；条码显示完整标签内容。标识可手动选中复制，多个未绑定标识分别列出，取出后随对应观察消失。其他识别来源仍按 R06 保留观察与冲突规则，但不能代替此入口要求的下位机本次 ID 匹配。冲突不能一键忽略变为成功。识别成功仍持续观察到首次开始，取出、更换药盒或全部有效观察消失时撤销匹配、禁用开始，重新识别；不能沿用上次缓存 ID。

保存长者的 RFID 绑定后同步本机识别资料；仍在轨道上且本次会话已观察到的标识重新核验，不要求重新领取任务，不下发机器动作。已取出的标识不因保存绑定重新变为在位。

## P07 执行台

默认主区域只突出当前长者、当前药物图片/名称/规格/投料形态、目标与累计进度，并提供醒目的暂停按钮。显示“准备中”“可投入当前药物”“等待完成反馈”等实际阶段；使用一处清楚的进度表达，避免把同一进度重复放进多个卡片。借鉴原型的下一药预告，但执行中仅显示简短药名与形态提示，不同时展开下一药的大图、完整计划和操作区；如没有下一药，不显示空预告。

准备下一药或换盘时，主内容、图片、开口控件均指向下一批药物，此时展开其规格、形态、目标数量及相关投料信息。同盘正常换药自动启动，主操作保持暂停；换盘仍等待识别与确认。预览计数从零显示，不能继承上一药的计数或最近开口值；上一药保留简短处理摘要，完整结果按需查看。药格默认折叠为“查看本盘摆药计划”，同步详情、完整设备资料和参数历史也由对应入口展开。普通执行状态不常驻异常表单、完整步骤列表或诊断字段。本机命令成功后立即刷新本机状态，中央资料刷新在后台进行，连接失败不能阻塞暂停、恢复等本机控制。

| 当前情况 | 可用操作 | 结果 |
| --- | --- | --- |
| 本药尚未启动 | 开始本药 | 保存启动并执行，随后可投料 |
| 本药执行中 | 暂停、调整开口、跳过、结束当前工作 | 显示请求及反馈；不提前宣称动作成功 |
| 暂停已确认 | 继续摆药、结束当前工作 | 按已保留进度继续，或进入结果核对 |
| 本药完成，同盘尚有下一药 | 自动切换并启动下一药；暂停 | 图片、计数和开口值立即切换到下一药，进入可投料阶段后换药即可直接投料，无需点击开始或完成 |
| 本盘完成，尚有下一盘 | 进入换盘 | 显示下一盘用途，开仓等待换盘 |
| 所有药处理结束 | 自动返回首页，结果可查 | 首页简短显示药盒反馈状态；不要求人工确认取盒 |

切换当前药物时，用约 680 毫秒表现卡片接替：宽屏下一药从右侧预告卡片的实际位置向左移动并展开为当前药，原当前药向左淡出；窄屏下一药从下方预告位置向上接替，原当前药向上淡出。移动过程中逐渐切换为当前药详情，后段才补入新的下一药预告，形成连续顺序，不在主区域凭空淡入另一张卡片。普通计数更新、暂停和继续不触发迁移，暂停按钮全程可用；减少动态效果时直接切换，窗口尺寸改变时立即落到最新状态。动画不驱动或延迟实际任务状态。

收到进度反馈更新 N/T；达到 100% 尚未收到完成时写“等待设备完成”，不显示总任务成功。

上表定义各阶段的完整操作能力，不要求所有按钮同级铺开。正常执行时暂停直接可见，“调整开口”可一步打开；跳过和结束等低频操作可收纳到清楚标识的“更多操作”。一旦发生异常，处理本次异常的必要动作直接呈现，不要求工作人员去更多菜单查找。收起面板只改变显示，不改变任务、设备状态或允许动作。

“调整开口”使用随内容收缩的紧凑弹窗，保留当前刻度、方向说明、滑块和完成按钮；内容区目标宽度 360 逻辑像素，窄屏受屏幕约束，不撑满页面高度，也不压缩滑块的触控高度。

执行台提供可一步展开的“阀门舵机 · 药物名称”组件，展开后可连续操作，无需反复打开：滑块与数值输入同步，使用 `0–1` 设备刻度、步长 `0.01`，不标注角度；数值越小开口越大，机械位置以现场为准。连续调整时等待最后一次变化，停止约 400 毫秒后自动下发当前有效值；松开滑块、数值输入失去焦点或按 Enter 时立即提交。没有“应用”按钮，初次显示、页面重载和重新连接不自动发送初值。准备下一药或换盘时标题明确指向下一药，提交携带任务及批次身份，药物已变化时保留输入并提示重新核对。

准备、执行、暂停和异常核对阶段可调整；未连接时只保留输入，不发送；离开页面、药物变化、断开连接或输入无效会取消尚未下发的调整。发送期间仍可继续调整，按顺序发送并只保留最新待发值，不积压中间位置。显示最近下发值，模拟操作明确标记。调整不重置计数、不重发矩阵、不自动恢复暂停，也不立即保存为处方参数；本批正常结束、学习开启且满足条件时，手动开口按 [04](04-device-contract.md#新参数与学习策略) 参与学习加权。启动前手动值沿用于本次药物；下一药按自身条目和学习开关选择参数。参数管理中的显式保存是另一个操作。

## P08 异常与人工处理

异常发生时立即呈现，统一面板首先显示当前长者与药物、异常、已知进度和下一步，简短标明本机身份。完整设备资料、计划范围及原始反馈等核对依据按需展开；影响现场判断的信息和必要处理动作直接可见，不放入深层菜单。只展示与本次异常有关的处理项，不同时铺开以下全部能力：

- 堵转：列出待解除电机，人员处理后逐项“已清理，解除”。
- 计数异常或中断：选需核对的日期/时段范围，输入最终数量或选择“已核对全部按计划补齐”，保存为人工结果。
- 跳过：记录原因及未完成/未知范围，进入“等待机器退出当前药物”，依次等待停转 ACK、退出 ACK 和 DONE，再进入下一药或开仓取盒。等待中不开放继续投料及舵机调整；反馈迟迟未返回时可用“反馈未返回，转入现场核对”，保留计数及处理请求事件，核对后重新处理，不自动重发数量矩阵。
- 工作台直接展示“跳过”，点击打开确认弹窗。显示当前长者、药名、规格、已有计数与目标；默认不勾选“将此药标记为已摆好”，确认按钮为“确认跳过”。勾选后按钮改为“标记已摆好”，表示人工已核对本药全部用量。弹窗底部“跳过所有”“取消”“确认跳过”并排，采用相同紧凑层级；“跳过所有”为红色文字按钮，不再占用整行，不显示额外解释语句；该按钮不使用单药勾选状态、不改写之前完成结果。取消恢复打开前状态；确认跳过按 R10 的设备退出与结果规则处理。
- 重连：中断面板保留最后已知进度，提供原绑定 HC-06 状态及“尝试重连”。蓝牙连接恢复后，用户可“继续分药”，先确认机器未断电/复位、原药盒及药物未换且原批次进度仍保留；只发送恢复命令，不从头重摆。已知复位转入人工核对。
- 结束此次分药（不记录）：设备中断或异常核对时可选，独立弹窗说明删除本次任务、结果及设备反馈，要求确认机器已安全停稳且药盒和药物已妥善处理。确认后无需硬件应答，先锁定本机任务再删除中央、本机数据；失败保留删除阶段并提供重试。完成后回准备清单，历史及导出不再包含该任务，不计入完成覆盖。该操作不发送开仓或收仓命令。
- 结果仍不清楚：允许保留“待核实”，不能要求人员编造数字才能退出。
- 主动关闭软件：提供“结束本次并退出”，明确本次不计完成与覆盖；先保存退出意图并请求停转，人员确认现场后取消。请求失败显示待处理，不因直接关闭页面而宣称停机。普通关闭是否删除全部记录待确认，显式“不记录”入口独立显示。

正常机器完成不弹出人工数量表单。无二级审批。

## P09 换盘、结果与取盒

换盘页面明确显示已完成与下一盘用途、同一长者及日期。完成本盘后机器开仓，清除上一盘的识别结果，再使用统一“药盒识别”组件自动核验。人员放好下一盘且识别通过后点击“已换好，继续摆药”；下一药仍显示药物提示。未识别、识别冲突或另一长者药盒时不能继续。

换盘保留当前动作图解与核验状态。所有药物处理结束后直接返回摆药首页，不显示独立取盒确认页。首页用简短状态提示药盒是否仍在轨道、是否等待轨道就绪；完整逐药结果从结果详情或历史记录查看。

药盒是否在轨道由下位机自动报告，用户无需点击“已取出”或“完成返回”。收到药盒离轨及设备就绪反馈后自动释放当前任务；状态缺失、掉线或收回未确认仍保留原结果并等待有效反馈，不把页面返回首页当作设备已就绪。正常完成、跳过最后一药及主动结束均遵循此行为；跳过和取消仍保留部分、未完成或待核实结果。

当前 UI 实现边界（2026-10-26）：执行结束自动回首页，结果快照及历史查询保留。`updateCollectionFeedback` 接受按记录身份区分的模拟在轨/离轨、未知、收回失败及就绪反馈；过期记录反馈无效，收到离轨与就绪后自动结束取盒，无人工确认。显式示例入口以定时模拟反馈演示自动更新；普通任务不以计时器推断药盒已取走。所有记录仍为会话内演练，未接下位机、真实检测或后端。

## P10 处方参数管理

从具体处方的药物条目或执行结果进入参数档案，显示所属长者、处方条目、当前值、版本、来源设备和投料形态。不同处方即使同药同规格也各自独立。

提供“调整参数”“保存参数”“查看历史”和学习开关。保存只作用于当前处方药物条目，与执行台临时开口提交分开。学习默认开启；开始批次时若关闭学习，则使用默认组且不生成学习结果，既有参数历史保留，完整选择规则见 [04](04-device-contract.md#新参数与学习策略)。转盘字段标明“初速度”，不显示为本批恒定转速；单次摆药内的自动调速由 STM32 负责。

药物、规格或形态变化时提示重新调整。保存期间发现版本变化，保留本次输入并提示刷新核对后重新调整，不静默覆盖。离线批次结果可查，但过时学习值不会覆盖当前参数；具体规则见 R14。

## P11 记录查询

从“摆药”模块内的“历史记录”进入全院授权范围查询，或从“处方管理”的长者详情进入该长者历史；侧栏不新增记录入口。

筛选长者、摆药日期、药物、设备、人员、结果及真实/演练环境。日期按业务时区计算首尾日边界，搜索支持姓名或床位；点击查询生效。排序支持时间正序和倒序，分页与导出使用同一组服务端筛选条件，不能只筛选已加载页。列表突出长者/床位、摆药时间、覆盖日期、设备名称和结果。详情采用宽抽屉，依次展示整体结果、逐药结果、人工处理经过；原计划和技术详情按需展开。模拟记录持续标记，缺失结果、未知结果不能标成完成。

提供“导出当前筛选结果”和“导出原始采样”。日期时段计划与设备累计报告分区标明，不能将计划格显示成逐格实测。导出状态可见，后台生成长导出时不阻塞执行台。

当前 UI 实现边界（2026-10-25）：P11 已有摆药模块内历史入口及长者详情入口，支持会话内查询、结果/待核实/日期/设备/人员筛选、时间排序和分页。详情包含逐药结果、原计划与处理经过；记录固定标记演练。空页可显式载入演练示例，查看示例并演示自动取盒反馈，不绕过准备入口的真实核验门槛。筛选、分页针对内存集合，不代表服务端查询、账号权限、长期保存或导出已实现。

2026-10-27 正式历史界面现已复用确认版卡片与右侧结果详情，并接通长者历史入口、原计划、处理事件分页及学习结果。现有 API 只返回最近 200 条已结束任务，界面明确标注当前筛选范围；不能以此宣称上文全历史服务端筛选与导出已完成。图案预览正式/演示共用原确认版网格与图例，正式数值只来自服务端快照。

## P12 设置、诊断与更新

应用设置只由管理员维护；本机连接配置与参数策略分开。保存时显示适用范围与生效时点，默认值不在本页面另行定义，引用 00。

设置从账户菜单打开，嵌入主工作区并保留可折叠主侧栏。参考用户提供的 Codex 设置层级，宽屏在内容区左侧显示设置搜索及分类导航，右侧显示当前分类标题和分组列表；窄屏改为单列搜索、分类选择与内容。分组采用细边框圆角容器，组内用分隔线区分条目，说明在左、控件在右，窄屏按需上下排列。工作人员直接通过主侧边栏切换到处方管理或摆药，不设置返回页、“返回工作空间”或退出设置步骤。

用户于 2026-10-27 确认：实体映射入口放在“设置 → 通用 → 药盒布局 → 实体位置映射”。点击“设置映射”显示当前机器，分别选择早、午、晚、睡前对应的机器行（0–3）及日期列方向；选择已被另一时段使用的行时交换两者，保持一对一。修改位置或方向后清除原现场核对状态，工作人员须实际核对后勾选确认。显式“保存映射”只更新当前设备的配置版本，不驱动电机、不重新连接；可以保存尚未核对的配置，但它不能用于实机计划。未选择设备时提示先保存设备，有任务时锁定修改，无维护权限时只读，保存冲突保留草稿。原设备面板不再重复编辑位置映射，取盒反馈仍在设备面板配置。

设置仅提供“通用”“外观”“关于”，移除“本机设备”分类、整组“图片显示”说明与演示重置入口；搜索跨分类匹配并提供空结果。真实模式和演示模式复用这套布局，不用临时账号管理页替换。当前不提供账号管理入口。演示模式的通用规则保留在本次会话；真实模式的准备天数、当天/次日起点、餐食分盘和睡前格均从服务器读取并由管理员保存，工作人员只读。强调色只保留本次会话。设备管理仅从摆药界面右上角状态按钮进入“我的设备”，设置内不另设入口；真实设备流程按后续阶段接通。

“通用”承载应用常规、摆药规则和药盒布局；“外观”承载强调色等界面偏好；“关于”展示版本、检查更新、自动下载更新开关和支持信息。常规显示当前账号和业务时区；摆药规则维护覆盖天数、漏摆起点、提醒和餐食分盘；药盒布局维护睡前时段和实体格的顺序。每个列表项左侧说明用途，右侧放输入框、选择、开关或操作按钮。

分类切换和搜索保留设置草稿。通用控件每次修改自动保存，等待时禁用重复修改并显示“保存中…”，服务端确认后显示“设置已保存”；失败保留草稿和原因，提供重试保存及放弃更改并重新加载。保存带预期版本，其他终端已经修改时不能静默覆盖。规则适用于之后生成的计划，历史快照不变。工作人员只读应用规则。搜索匹配分类及设置关键词，未找到时显示空结果。本机名称和连接信息在右上角“我的设备”面板展示，不通过保存应用规则触发；正式设备流程在该面板内提供 Android 蓝牙权限、配对、选定 HC-06 和固定本机绑定，区分已连接和已收到有效反馈，不将连接成功标成实机验证通过。传输配置与通信依据统一见 [04](04-device-contract.md#现有传输方式)。

首次安装由维护人员提供安装包。“关于”展示实际安装版本、“检查更新”及默认开启的“自动下载更新”开关，偏好持久化。更新弹窗显示版本、说明、大小、下载进度与错误；下载完成后，等待任务、收仓和补传结束，才启用“安装更新”。首次需要系统安装来源授权时显示“允许安装更新”；系统安装会话就绪后显示“继续系统安装”，也可取消安装。关闭弹窗不取消下载或解除安装锁；退出登录前须完成或取消安装。当前运行平台不支持、尚无发布或连接失败分别说明，不能误报“已是最新版本”。完整规则见 R15。

支持页显示应用版本、可得固件版本、连接状态、最后同步时间及待同步记录数，可导出诊断包。敏感业务附件仍遵守账号权限；诊断不要求用户阅读代码。

### 2026-10-27 正式界面恢复

真实入口沿用已确认的白灰极简风格、可折叠侧栏与账户设置菜单，默认打开摆药。待准备/提前准备、药物数、计划日期及校验问题来自服务端 `/preparation`，不调用演示模型或在界面重算覆盖；默认按剩余含当天不超过 2 天提醒。支持姓名/床位搜索、空状态、失败重试。执行主卡片显示任务快照药名、规格、投料形态、累计数量和进度，下一药简短预告；暂停/继续和现场异常操作保留。服务端尚无药品图片附件字段，因此正式主卡片诚实显示缺图占位，不能使用演示照片冒充实际药品。当前开口调整是一键弹窗，取盒阶段保留任务状态和首页清单。设备状态只出现在摆药顶栏；映射入口仍在药盒布局。关于页现按 R15 接入 Android 应用内更新，其他平台不提供安装入口。验证与后续调整见 [正式界面恢复报告](validation/2026-10-27-production-ui.md)。
