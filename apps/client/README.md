面向 Android 平板首发，沿用已确认的极简 UI。2026-10-26 在 NT 分支接入真实账号、长者、处方及版本，中央服务在同机 WSL/Conda 运行。执行计划见 [09](../../docs/09-agent-development.md)，Android 最新证据见 [2026-10-27 报告](../../docs/validation/2026-10-27-android.md)，Windows 闭环见 [执行报告](../../docs/validation/2026-10-26-execution.md)。

## 显式演示模式

下文的准备、执行、历史与可编辑演示规则仅适用于 `--dart-define=PILLXAI_DEMO=true`。该模式使用虚构内存资料，登录为 `admin` / `admin123`，不调用真实业务 API、不控制机器。它保留既有交互回归，不能作为生产任务入口。

每种药完成后，下一药从预告卡片的实际位置移动并展开为当前药，原当前药退出，随后补入新的下一药预告；宽屏从右向左接替，窄屏从下向上接替，全程约 680 毫秒。计数和开口值重置后直接进入下一药的摆药状态，无需再点击“开始本药”，主操作保持“暂停”。最后一种药完成后自动返回待摆清单，结果保存在历史；药盒状态按下位机反馈更新，不要求人工确认取盒。当前自动计数仍为定时器演示，没有药物更换检测或设备动作。

## 结果、取盒与历史记录（2026-10-25）

正常完成、最后一药跳过、批量跳过及主动结束均直接返回摆药首页，结果保存在历史。正常完成、人工确认、跳过、待核实、未执行分别展示；主动结束保留已完成药物和当前计数，不增加完整覆盖。结果快照保存当时的长者、药物、计划、原计数和独立人工确认量，后续处方修改不改写历史。跳过弹窗底部将红色“跳过所有”与“取消”“确认跳过”并排，保留单药与批量结果差异。

首页简短显示药盒反馈状态，取消独立取盒页及人工确认按钮。`updateCollectionFeedback` 接受当前记录的模拟在轨/离轨、未知、收回失败和就绪反馈；离轨且就绪后自动释放任务。未知或过期反馈不会解除占用。普通任务不以超时假定药盒离轨；只有显式示例演示用定时器输入反馈。未完成取盒时仍不能新开任务、退出或更改连接，跨页保留状态；未接真实设备或后端。

历史入口位于摆药清单与长者详情，侧栏仍为三个入口。支持姓名/床位/药物查询、结果和待核实筛选、摆药日期、设备/人员筛选、时间排序与每页 10 条。详情为宽面板，包含逐药结果、原计划与处理经过。仅对当前会话的内存记录查询，不提供服务端查询或真实同步、导出。

浏览器体验路径：登录 → 摆药 → 历史记录 → 载入演练示例 → 王奶奶记录 → 演示自动取盒反馈 → 自动返回首页并更新状态。示例仅显式载入一次，不更新真实资料或覆盖；不绕过准备页的药盒核验限制。

`lib/models/dispense_record.dart` 定义不可变的会话结果快照；`results_page.dart` 与 `history_page.dart` 分别负责首页药盒提示/详情和查询。`test/results_test.dart` 验证结果来源、取消与跳过、自动反馈与取盒保护、未知/失败恢复、快照不被处方修改、历史筛选和三尺寸闭环。截图可用 `--dart-define=RESULTS_CAPTURE=<仓库外绝对路径>` 输出。

## 本地运行与构建

以下命令在**仓库根目录**的 PowerShell 中执行。项目当前使用 Flutter **3.47.1**、Dart **3.13.1**；依赖清单及锁定结果见 [pubspec.yaml](pubspec.yaml) 与 [pubspec.lock](pubspec.lock)。

统一入口 [scripts/flutter.cmd](../../scripts/flutter.cmd) 调用仓库内 `.tools/flutter`，自动切换到 `apps/client`。Pub、Gradle 和 Android 用户缓存均指向仓库 `.tools`；脚本仅配置当前进程，不改全局 PATH 或注册表。Android 构建使用本机已有 Android SDK 和 Android Studio JBR，可通过当前进程的 `ANDROID_SDK_ROOT`、`JAVA_HOME` 指定已有路径。

安装项目依赖、静态检查和测试：

```powershell
.\scripts\flutter.cmd pub get
.\scripts\flutter.cmd analyze
.\scripts\flutter.cmd test
```

构建并打开显式演示预览（真实资料版本使用上面的命令）：

```powershell
.\scripts\flutter.cmd build web --release --no-web-resources-cdn --dart-define=PILLXAI_DEMO=true
node .\scripts\serve-preview.cjs
```

服务启动后打开 [localhost:5180](http://localhost:5180/)；它只监听本机 `127.0.0.1:5180`，提供 `apps/client/build/web` 中的构建产物。修改代码后重新构建并刷新浏览器。结束预览服务可在对应终端按 `Ctrl+C`。

需要热重载时，可启动 Flutter 的开发预览：

```powershell
.\scripts\flutter.cmd run -d chrome --dart-define=PILLXAI_DEMO=true
```

查看已连接终端、运行到指定设备，以及构建 Android 调试包：

```powershell
.\scripts\flutter.cmd devices
.\scripts\flutter.cmd run -d <device-id>
.\scripts\flutter.cmd build apk --debug
```

将 `<device-id>` 替换为设备列表中的实际 ID。Android Debug APK 输出为 [build/app/outputs/flutter-apk/app-debug.apk](build/app/outputs/flutter-apk/app-debug.apk)，可复制到 Android 平板手动安装体验。它是调试预览包，不是正式签名发布包。

## 代码导读与触屏约定

从 `main.dart` 的 `PillxaiApp` 读起：默认进入 `ConnectedWorkspace`，应用会话持有 API 连接及当前会话的 controller；演示模式才创建 DemoModel。页面持有输入、筛选和滚动状态。`setState` 更新局部状态，controller 在查询或保存结束后通知页面。下面的计划与任务导读仅属于演示模式。

入口按职责阅读：`build` 配置应用主题与语言 → `_buildHome` 判断登录并排列左侧导航、右侧内容 → `_buildHeader` 显示标题与设备入口、`_buildPages` 选择页面。这些辅助方法属于同一个 `State`，首次阅读先看 `_buildHome` 的区域关系，再进入对应方法查看细节。回调中的 `setState` 才会修改会话状态，构建方法本身只返回界面配置。处方管理和设置页不显示任务提示条；通过侧栏“摆药”回到当前任务，切页仍保留任务状态。

侧栏胶囊图标保存在 `assets/icons/capsule.svg`，由 `workspace_sidebar.dart` 中的 `SvgPicture.asset` 加载；修改图形时编辑 SVG。依赖 `flutter_svg` 的版本在 `pubspec.yaml` 和锁文件中固定。

准备只有一条主线：`DemoModel.planFor` 根据覆盖起点生成 `PreparationPlan` → `PreparationDialog` 选择天数并展示校验结果 → 最新药盒反馈匹配后调用 `startPreparedTask(plan)` → 执行页用 `pause` / `resume` 控制同一任务。构造模型时不创建任务；`resume` 不能首次启动。任务状态通过只读 getter 对外提供。测试也通过同一计划和启动入口，短任务样例集中在 `test/support/tasks.dart`，不再维护另一套准备状态机。

注释采用教学式契约：说明职责、输入与返回值、前置条件、副作用和关键不变量；纯计算函数附小例子，异步位置说明 `mounted` 和身份核对，资源位置说明创建/释放关系。注释解释“为什么这样写”，普通间距和圆角不逐行翻译。建议接着读 `dose_rules.dart` → `preparation_plan.dart` → `demo_model.dart` 的启动/暂停/计数，再回到对应按钮回调。`test/robustness_test.dart` 提供可运行的边界例子。

处方在当前日期范围内有校验问题时仍出现在待摆清单；已结束或本周期尚未开始的药不参与布局校验。表单与计划共用剂量规则；数值保护上限 `maxPreviewDose` 仅限制预览程序支持的数值范围，不代表临床允许用量或硬件容量。每格最多画24颗圆点，超出时改为精确数量摘要，可点按查看逐药数量；计划数量不被截断。

平板宽屏下，长者名单和详情独立滚动，搜索与添加固定可达，点选后详情回到顶部；窄屏或可用高度不足时纵向排列，点选后定位到详情。按钮、选择器和菜单行的触控目标至少48逻辑像素，保留轻巧图标与原有白灰风格。侧栏高度可随字体增长，短屏可滚动；表单中部适应软键盘并可拖动收起键盘，系统返回和“取消”使用同一未保存保护。浅色强调色保留填充原色，文字、滑块和日历选中态使用可读颜色。
