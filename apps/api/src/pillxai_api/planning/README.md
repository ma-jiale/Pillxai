# 计划预览

责任：把当前长者、处方版本和应用设置转换为可核对的计划快照；不控制设备、不创建执行任务、不声明已摆好覆盖。

公开入口为 `POST /residents/{resident_id}/plans/preview` 和 `GET /plans/{plan_id}`；请求与响应模型在 `models.py`，经统一 OpenAPI 命令生成 Dart SDK。`engine.py` 为无存储副作用的计算入口，`routes.py` 管理事务、快照保存和版本核对。依赖资料模块的公开查询入口及应用设置，不依赖 Flutter 或设备模块。

POST 读取设置与长者锁，和处方保存使用相同锁顺序，保证快照来源一致。服务端按 Asia/Shanghai 计算业务日期，按设置从当天或次日起算；所有药都在未来生效时从最早生效日开始。有限疗程含首尾日，裁去尾部空日期、保留中间空列；停用药不参与。半片用 Decimal 换算为颗粒，原片等价量单独保留。饭前盘与其他餐食关系盘按设置分组；睡前需求不能被关闭的第四格默默隐藏。

预览允许覆盖本次 1–7 天天数和餐食分盘，不修改长期设置。快照含长者版本、完整处方来源、设置版本、日期、时段和每药按日期 × 早午晚睡前排列的颗粒矩阵。显示层只渲染矩阵；未启用睡前时第四列为零且不展示。`plan_previews` 保留生成时内容，GET 根据当前资料/处方/设置版本及业务日期标记是否过期，不改写原快照。

当前只完成 M2 的预览部分：已有覆盖的续接、重叠安排保护、任务归属、启动许可、药盒绑定/识别、实体位置映射和执行仍未实现。因此反复生成预览不会向后推进日期，也不会触发机器动作。

实际验证：后端 `test_planning.py` 覆盖规则、设置 CAS 与跨应用重读；客户端 `server_planning_test.dart` 覆盖失败草稿、宽窄屏、按服务器矩阵渲染和过期禁止继续；`tool/check_planning.dart` 已通过真实生成 SDK、API 和 PostgreSQL 往返。运行命令见 API 与客户端 README。
